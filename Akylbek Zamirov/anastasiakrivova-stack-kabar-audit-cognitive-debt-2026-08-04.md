### Расчёт оценки

Оценку повышают ясное назначение продукта, навигация по пакетам и общее соответствие API-документации маршрутам. Её снижают отсутствие исполнимых спецификаций, decision records и агентского контекста, а также расхождение конфигурации origin.

По весам пяти критериев: `6×0,25 + 2×0,20 + 5×0,20 + 0×0,10 + 5×0,25 = 4,15`; ограничивающие caps не применялись, после перевода на шкалу 100 и округления итог — **42/100**.

Уверенность **средняя**: код, README и текущая структура доступны. Ничего не исключалось из пяти критериев из-за недоступного внешнего контекста; однако неглубокая история, отключённые GitHub Issues, отсутствие pull request с обсуждениями и внешнего авторитетного продуктового источника ограничивают выводы о прошлых обоснованиях.

### Карта намерений

- Цель продукта сохранена в `README.md:3`; назначение backend и client — в их README.
- Ограничения JWT auth, CORS/cookies и uploads описаны в `backend/README.md` и частично подтверждаются маршрутами и конфигурацией.
- Важные правила topics — только в `backend/src/services/topic.service.ts`, `chat.service.ts` и `message.service.ts`.
- Причины выбора JWT cookies, Socket.io room model, тем в supergroup и WebRTC signaling не закреплены в ADR/RFC или другом decision record.

### Путь к продуктовому контексту

Новый читатель начинает с `README.md` и переходит в `backend/README.md`, `client/README.md` или `websocket-example/README.md`. Этот путь достаточен для настройки и обзора возможностей, но не ведёт к спецификации целей, ограничений, терминов или решений; после README следующим источником правды становится реализация.

### Исполнимое намерение

В основном backend/client не найдены `*test*`, `*spec*`, `*.feature`, fixtures или golden-файлы, а package scripts не предлагают test command. `websocket-example` — ручной учебный сценарий и не доказывает поведение Kabar. Поэтому auth, chat, topic/message routing, realtime events и calls не имеют автоматического сигнала при нарушении ожидаемого контракта.

### Восстановление понимания

README позволяют восстановить состав системы и локальный запуск. Неочевидные rationale и сквозные потоки приходится собирать из нескольких файлов: например, topic разрешён только для supergroup, `General` создаётся автоматически, а сообщение без `topicId` направляется в него. Нет глоссария, документа адаптации, критериев приёмки или архитектурного индекса.

### Согласованность

Документированные chat endpoints в целом соответствуют определениям маршрутов, а учебный Socket.io-пример явно отделён от production stack. Конфликт обнаружен в `FRONTEND_ORIGIN`: `README.md`, `backend/.env.example` и часть `backend/README.md` указывают `5173`, тогда как runtime default и другая строка `backend/README.md` указывают `5174`. При малом числе спецификаций более широкое сравнение intent, docs и behavior ограничено.
